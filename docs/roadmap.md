# Hoja de ruta

Prioridad: facilitar una candidatura concreta, usando el aviso y hechos del perfil. Las propuestas no están implementadas ni autorizan por sí solas publicar.

## 1. Preparar postulación: siguiente diseño
Entrada: botón dentro de cada oportunidad. Una zona compacta, sin crear otro dashboard.
- Preguntas basadas en requisitos sin evidencia: herramientas usadas, casos reales y resultados verificables.
- Respuestas editables por candidatura; incorporar al perfil solo con aceptación expresa.
- Carta breve basada en oferta, perfil y respuestas aceptadas. No inventar experiencia ni afirmar habilidades pendientes.
- Evidencias sugeridas: proyectos, resultados o muestras que realmente existan.
- Flujo: borrador -> revisar/editar -> guardar -> copiar/descargar. No envío automático.
- MVP gratuito: reglas y plantillas; distinguirlo de generación con IA. Integración paga solo tras decisión posterior.

Aceptación: no mezclar datos de ofertas; guardar por propietario y empleo; permitir reabrir borrador; detectar cambios de perfil/aviso para solicitar revisión; manejar avisos incompletos; no elevar afinidad solo por generar texto.

## 2. CV enfocado y entrevista
Seleccionar logros relevantes sin alterar hechos; exportar una versión identificable. Preguntas de entrevista con guía de ejemplos reales, sin presentar preguntas como garantizadas.

## 3. Seguimiento y aprendizaje
Registrar versión enviada y próximos pasos. Medir respuestas reales a postulaciones, sin inventar eventos históricos ni atribuir causalidad al puntaje.

## Mantenimiento previo o paralelo
Endurecer entradas importadas, fallback de portal, pruebas de datos parciales; reconciliar Git local/remoto; revisar portabilidad de los tests en Linux; instalar Job Match por separado donde se use.
